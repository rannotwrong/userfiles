# 用户日记微信小程序上线操作手册

本手册对应 `mp-1.0.0`。代码侧已支持开发版使用本地 HTTP 后端，体验版和正式版使用微信云托管。

## 1. 你需要提前准备

- 微信小程序账号管理员权限。
- 正式 AppID。
- 微信小程序 AppSecret；只填写到云端环境变量，不写入代码或聊天。
- 当前 Supabase 项目的 URL 和 `service_role` key；只填写到云端环境变量。
- 火山方舟 `ARK_API_KEY`；只填写到云端环境变量。
- 微信公众平台已经完成主体信息和小程序备案。

## 2. 替换正式 AppID

1. 登录微信公众平台：`https://mp.weixin.qq.com/`。
2. 进入“小程序后台 → 开发 → 开发管理 → 开发设置”。
3. 复制 AppID。
4. 打开 `miniprogram/project.config.json`。
5. 将 `"appid": "touristappid"` 替换为真实 AppID。
6. AppSecret 不要写入这个文件。

## 3. 执行 Supabase 数据库迁移

当前首版沿用 Supabase，以便最快形成体验版。

1. 登录 Supabase 控制台并打开当前 Web 项目。
2. 进入 `SQL Editor`。
3. 新建查询。
4. 完整粘贴 `supabase/wechat-auth-migration.sql`。
5. 点击 `Run`。
6. 在 `Table Editor` 中确认存在：
   - `wechat_users`
   - `wechat_audience_users`
   - `wechat_live_records`
7. 不要把 `service_role` key 放进小程序代码。

此迁移会创建小程序独立数据表，不会覆盖网页版数据。

## 4. 创建微信云托管服务

1. 登录微信公众平台。
2. 进入“云开发 → 云托管”；如果后台入口名称不同，可在后台搜索“云托管”。
3. 选择当前小程序并创建一个生产环境。
4. 记录环境 ID，例如 `prod-xxxxxxxx`。
5. 创建服务，服务名填写 `user-atlas-api`。
6. 部署方式选择“代码包”或“代码仓库”。
7. 服务根目录选择 `user-profile-miniprogram/server`。
8. 构建方式选择 Dockerfile。
9. 服务端口填写 `3000`。
10. 健康检查路径填写 `/api/health`。
11. 首次部署先保持一个最小实例；稳定后可按实际访问量调整。

## 5. 配置云端环境变量

在 `user-atlas-api` 的“服务设置 → 环境变量”中逐项添加：

| 变量名 | 填写内容 |
|---|---|
| `PORT` | `3000` |
| `WECHAT_APP_ID` | 正式小程序 AppID |
| `WECHAT_APP_SECRET` | 小程序 AppSecret |
| `SUPABASE_URL` | 当前 Supabase 项目 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role key |
| `SESSION_JWT_SECRET` | 本地生成的至少 32 位随机字符串 |
| `SESSION_TTL_DAYS` | `30` |
| `ARK_API_KEY` | 火山方舟 API Key |
| `DOUBAO_VISION_MODEL` | `doubao-seed-1-8-251228`，如控制台实际模型 ID 不同则用实际值 |
| `JSON_BODY_LIMIT` | `8mb` |
| `LOGIN_RATE_LIMIT` | `30` |
| `OCR_RATE_LIMIT` | `20` |

macOS 可在终端执行下面命令生成 JWT 密钥，只复制输出值到云端：

```bash
openssl rand -base64 48
```

保存变量后重新部署服务。在云托管日志中确认服务启动，并访问健康检查，预期返回：

```json
{"ok":true,"service":"user-profile-miniprogram-server"}
```

## 6. 填写云托管环境 ID

1. 打开 `miniprogram/utils/config.js`。
2. 找到体验版和正式版中的 `REPLACE_WITH_CLOUD_ENV_ID`。
3. 两处都替换为第 4 步记录的环境 ID。
4. 如果服务名不是 `user-atlas-api`，同时修改 `cloudService`。
5. 在 `server/` 中运行 `npm run check:release`，必须显示发布自检通过。

## 7. 配置微信隐私保护指引

1. 在小程序后台找到“用户隐私保护指引”或“服务内容声明”。
2. 声明小程序会处理的内容：
   - 微信用户标识：用于登录和隔离不同用户的数据。
   - 用户选择的照片或视频信息：用于读取用户主动选择的直播截图并进行识别。
   - 用户主动填写的信息：昵称、生日、互动备注、消费和直播数据，用于生成用户档案。
3. 图片用途应写明：用户主动选择直播截图后，发送至服务端调用图像识别服务提取直播数据；结果展示给用户修改确认。
4. 第三方处理者应按火山方舟控制台协议中显示的实际服务主体填写，不要猜测公司名称。
5. 保留期限建议写明：原始截图仅在识别请求期间临时处理，不作为业务档案长期保存；结构化结果保存至用户主动删除或注销账号。
6. 发布隐私保护指引。
7. 在体验版中点击“上传聊天或直播截图”，确认微信隐私授权能够正常出现。

## 8. 导入并生成体验版

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择 `user-profile-miniprogram/miniprogram`。
4. AppID 选择正式小程序 AppID。
5. 在“详情 → 本地设置”中开启 ES6、增强编译；不要在体验版测试中勾选“不校验合法域名”。
6. 编译并在开发者工具完成一次微信登录。
7. 点击工具栏“上传”。
8. 版本号填写 `1.0.0`。
9. 项目备注填写：`微信登录、用户档案、直播记录、截图识别、账号数据删除`。
10. 回到小程序后台，将该开发版本设置为体验版并添加体验成员。

## 9. 体验版验收

使用两个不同微信账号完成：

1. 首次打开必须先同意协议。
2. 微信登录成功。
3. 新增、编辑、删除用户档案。
4. 上传截图后出现隐私授权，图片识别成功。
5. 修改识别结果并保存直播记录。
6. 删除直播记录。
7. 退出后重新登录，数据仍存在。
8. 第二个微信账号看不到第一个账号的数据。
9. 删除账号后重新登录，应创建全新空账号。
10. iPhone 和 Android 各完成一次完整流程。

## 10. 提审和发布

1. 在小程序后台进入“版本管理”。
2. 选择 `1.0.0` 开发版本并提交审核。
3. 服务类目选择与后台实际可用类目相匹配的工具类目。
4. 功能说明填写：

   `本小程序用于主播个人记录直播间用户互动情况。用户通过微信身份登录，可创建用户档案、录入直播记录，并上传本人有权处理的直播截图进行信息提取。小程序不提供公开社交、交易或付费功能。`

5. 测试路径填写：

   `微信登录 → 首页新增用户 → 上传直播截图或输入文字 → 核对识别结果 → 保存直播记录 → 数据与账号。`

6. 审核通过后点击“发布”。
7. 正式发布后使用不在开发者名单中的普通微信账号再完整验收一次。

## 11. 当前上线边界

- 小程序数据与网页版数据暂时独立。
- 当前数据库仍为 Supabase。准备公开运营或扩大用户规模前，需要确认数据存放地域、跨境处理和网络稳定性；如不满足要求，再迁移到国内数据库。
- 原始截图不写入数据库，但会在 OCR 请求中由服务端和模型服务临时处理。
